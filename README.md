# ReqAssist

LLM-ассистент системного аналитика: проверяет бизнес-требования (БТ) по чеклисту, предлагает правки и генерирует функциональные требования (ФТ) по шаблону. Проект делается в рамках курса ML System Design (ИТМО).

## Проблема

Аналитик тратит много времени на рутину:

- сверяет БТ с внутренним чеклистом качества и вручную ищет пропущенные разделы
- собирает БТ из расшифровок встреч с заказчиком
- переносит содержимое БТ в шаблон ФТ и заново форматирует документ под Confluence

Ошибки в БТ (не описаны интеграции, критерии приёмки, граничные случаи) обнаруживаются поздно: на ревью ФТ, в разработке или в тестировании. Чем позже найдена ошибка, тем дороже её исправить.

## Решение

Веб-приложение, встроенное в рабочий контур аналитика (Confluence + Jira), с тремя сценариями:

| Сценарий | Вход | Выход |
| --- | --- | --- |
| Валидация БТ | страница БТ из Confluence + чеклист (стандартный или свой) | скор полноты, покрытие чеклиста по пунктам, список правок, которые можно применить в один клик |
| Генерация БТ | расшифровка встречи (текст или аудио) | черновик БТ по стандартной структуре с маркерами `[уточнить: ...]` |
| Генерация ФТ | проверенные БТ + шаблон ФТ | документ ФТ, сохранённый в Confluence, и задачи в Jira |

Ядро решения - LLM (GigaChat) с промптами под каждую задачу, детерминированный пост-процессинг ответа и многоуровневая защита от prompt injection.

## Ключевые метрики

- **Бизнес**: время подготовки БТ/ФТ, количество итераций ревью до согласования, доля дефектов требований, найденных после передачи в разработку
- **ML / LLM**: согласие оценки чеклиста с экспертом-аналитиком, стабильность скора при повторных запусках, доля принятых правок, доля галлюцинаций в ФТ
- **Безопасность**: detection rate атак prompt injection и false positive rate на реальных документах
- **Технические**: латентность валидации и генерации, доля ответов LLM, которые не удалось распарсить

Подробнее - в [дизайн-документе](docs/ml_system_design_doc.md).


Код приложения (Node.js + React) живёт в отдельном рабочем репозитории; здесь лежат артефакты курса: дизайн-документ, эксперименты и ML-часть по мере выполнения домашних заданий.

> ReqAssist - реальный внутренний продукт. Название организации, внутренние адреса систем, реальные документы и чеклисты в этот репозиторий не попадают: в документации они заменены обобщёнными формулировками.

## Разработка

Нужны [uv](https://docs.astral.sh/uv/) и Python 3.11+.

```bash
uv sync
uv run pre-commit install
```

Проверить весь репозиторий вручную:

```bash
uv run pre-commit run --all-files
```

Что проверяют хуки:

- `ruff-check` и `ruff-format` - линтер и форматтер Python-кода
- `markdownlint-cli2` - стиль markdown-документации
- `pre-commit-hooks` - пробелы в конце строк, перевод строки в конце файла, валидность YAML/TOML/JSON, конфликты слияния, большие файлы, приватные ключи, запрет прямых коммитов в `main`
